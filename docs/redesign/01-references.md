# 레퍼런스 분석

2026-10-08 작성. 레퍼런스는 kciter.so 한 곳. 결정 칸은 비워 둠(고정 / 참고 / 버림 중 하나로 채우기).

## 측정 조건

- **값:** headless Chrome(DevTools 프로토콜)으로 페이지를 열고 `getComputedStyle`로 뽑음. 색은 hex로 바꿔 적음.
- **화면:** 데스크톱 1440×900, 모바일 390×844(모바일 에뮬레이션, 2배 해상도)
- **동작:** TOC·검색·댓글·시리즈는 실제 Chrome에서 스크롤·클릭해서 확인
- **내 블로그:** 실제 사이트(https://alexization.github.io). 디자인은 `redesign` 브랜치와 같음
- **줄간격 괄호 안 숫자:** 글자 크기 대비 배수(예: 16px / 28px → 1.75)

## 요약

- **가장 큰 차이는 "덜 하는 것".** kciter는 본문·제목 자간을 건드리지 않고(`normal`), 색은 회색 계열 + 포인트 1색(인디고 `#5c6ac4`), 카드·상자 모양도 한 가지를 반복함. 내 블로그는 음수 자간, 파란 포인트, 어두운 코드 블록, 테두리 카드 TOC가 같이 있음.
- **본문 칸 배치가 다름.** kciter는 715px 칸을 화면 가운데 두고 TOC를 칸 밖 오른쪽 여백에 띄움. 내 블로그는 본문(728px)+TOC(304px)를 한 덩어리로 묶어서 본문이 왼쪽으로 치우침(x=180).
- **TOC는 접힘이 핵심.** kciter는 큰 섹션만 보이고, 지금 읽는 섹션의 소목차만 펼침(이 글 기준 처음엔 11개 중 4개만 보임). 내 블로그는 소목차가 항상 다 펼쳐져 있고, 현재 위치 표시는 파란 글자뿐.
- **라이선스:** kciter 글꼴(Pretendard·Quattrocento Sans·Source Code Pro)과 코드 테마(github-light)는 전부 무료. 못 가져오는 건 kciter 고유 그림(일러스트·썸네일·배경 그라데이션 등)뿐. 내 블로그의 Toss Product Sans는 이미 빼기로 함(C05).

## 2. 공통 패턴 (kciter 전반)

레퍼런스가 한 곳이라, kciter의 여러 페이지에서 반복되는 원칙을 모음.

- **715px 한 칸.** 헤더, 글 본문, 글 목록, 홈 섹션이 전부 같은 715px 칸에 가운데 정렬. TOC만 칸 밖으로 뺌. 그래서 어느 페이지든 시선이 같은 세로줄에 머묾.
- **색은 회색 + 한 색.** 글자는 회색 계열 몇 단계(`#212b36`, `#454f5b`, `#666`, `#9a9a9a`)이고, 포인트는 인디고 하나. 코드 블록도 흰 바탕이라 본문 흐름을 끊지 않음.
- **같은 모양 반복.**
  - 카드: 흰 배경 + 1px `#eee` 테두리 + 둥글기 12px
  - 연한 회색 면: TOC 현재 위치(`#f4f6f8`), 시리즈 상자(`#f8f9fa`), 코드 창 머리(`#f6f8fa`)
  - 연한 인디고 면: LATEST 배지, 검색 결과 일치 부분
  - 알약 모양: 태그
- **글자 단계가 적음.** 본문 16px, 제목 32 / 25.6 / 20.8px(2rem / 1.6rem / 1.3rem), 보조 글자 12~13.6px. 굵기는 400 / 600 / 700만. 본문·제목 자간은 `normal`이고, 대문자 라벨(LATEST 1.5px, 코드 언어 이름 0.5px, ARTICLES 같은 섹션 이름)만 자간을 넓힘.
- **필요할 때만 보여 줌.** 소목차는 그 섹션에 들어가야 펼쳐지고, 읽기 시간은 목록에만, 글 제목 아래엔 날짜만, 태그는 글 끝에 작게. 댓글도 근처에 와야 불러옴.
- **영어 UI 문구.** "Written on", "min read", "Latest", "All articles" 등.

## 3. kciter 강점

좋다고 한 점과 연결해서 정리.

| 좋다고 한 점 | 실제로 만드는 요소 |
|---|---|
| 코드 블록이 읽기 편함 | 밝은 테마라 본문과 같은 흰 바탕. 창 머리(점 3개 + 언어)로 "여기부터 코드"가 분명함. 줄 번호와 세로 구분선, 은은한 그림자. 본문보다 작은 13px라 코드가 글을 누르지 않음 |
| 절제력, 가독성 | 자간 `normal`, 포인트 1색, 장식 없는 제목(구분선 하나). 본문 칸이 화면 가운데 고정 |
| 글꼴·크기·간격 | 본문 16px / 1.75, 문단 위아래 같은 16px, 제목 위 48px로 섹션 사이가 넉넉함 |
| TOC가 적절, 소목차 펼침 | 큰 섹션만 보이다가 그 섹션에 들어가면 소목차가 펼쳐짐. 현재 위치는 회색 면으로 표시해서 한눈에 보임. 테두리·제목이 없어 본문 옆에서 조용함 |
| 최신 글 크게 + 나머지 나열 | 최신 글은 16:9 큰 이미지 카드, 나머지는 같은 높이(136px) 가로형 카드. 위계가 두 단계뿐이라 단순함 |

그 밖에:
- 시리즈 상자: 연재 글(Home Lab, Git Ranker)이 많은 내 블로그에 잘 맞음
- 검색 모달: 다른 페이지로 안 가고 그 자리에서 결과를 보여 줌
- 글 끝 작성자 카드: 프로필을 사이드바 대신 글 끝에 둠

## 4. 피해야 할 점

### kciter에서 그대로 가져오면 안 되는 것

- **제목 줄간격 28px 고정.** 32px 제목에 28px 줄간격이라, 제목이 두 줄이 되면 줄이 겹치듯 붙음. 내 글 제목은 길어서(`[Home Lab #4] 홈서버 도메인 정규화: …`) 두 줄이 흔함.
- **TOC가 1400px 이하에서 숨음.** 1280·1366px 노트북에선 TOC가 안 보임. 내 결정(C09)은 1024px 미만 숨김.
- **본문 줄바꿈 `normal`.** 한글 단어 중간에서 끊김. C16 결정(본문은 `keep-all` 유지)과 반대.
- **모바일 본문 14px.** 지금 내 블로그(16px)보다 작아짐.
- **날짜 형식 4가지 혼용.** 한 가지로 통일하는 게 나음.
- **인라인 코드 빨간 글자.** 내 글은 인라인 코드가 많아서(분석한 글은 첫 두 문단에만 4개) 빨간색이 많이 보일 수 있음.
- **코드 글꼴에 한글 없음.** Source Code Pro엔 한글이 없어서 한글 주석은 다른 글꼴로 섞여 나옴.
- **태그가 링크가 아님.** 태그 페이지를 유지하기로 했으니(C04) 이 방식은 안 맞음.

### 내 블로그에서 버릴 것

- 음수 자간: 본문 -0.01em, 제목 -0.035em `[답답]`
- 문단 위 24px / 아래 8px 비대칭, 제목 아래 4~8px로 본문에 붙음 `[답답]`
- 목록 글자색(`#4e5968`)이 본문(`#333d4b`)과 다름
- 인용문 글자가 본문보다 큼(19px) `[답답]`
- 흰 본문 사이에 어두운 코드 블록(`#263238`) `[가독성]`
- 본문이 왼쪽으로 치우친 배치(x=180) `[가독성]`
- TOC: 테두리 카드 + 항목마다 구분선 + 소목차 항상 펼침 + 파란 글자만으로 현재 위치 표시 `[TOC]`
- 오류로 이미 잡힌 것: E04(태블릿 TOC), E06(인라인 코드 넘침), E07(푸터 정렬), E08(검색 결과), E10(영어 날짜), E15(읽기 시간), E16(관련 글)
