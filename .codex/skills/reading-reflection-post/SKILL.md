# Reading Reflection Post

## Overview

Turn outside reading and the user's own thinking into one coherent Korean post.
Treat references as lenses that sharpen the user's stance, not as content to summarize in order.

## Workflow

1. Read every provided source and every user draft before deciding structure.
2. Identify the user's real discomfort, question, changed perspective, or unresolved tension.
3. Extract one dominant thesis and at most two supporting axes.
4. Assign each source one role: question reframing, concept, evidence, counterpoint, or closing support.
5. Merge overlapping draft material by argument, not by original file order.
6. Build one arc from opening tension to closing stance.
7. Write from scratch in the user's voice instead of stitching old paragraphs together.
8. If the user asks for a file, create the markdown file directly.

## Preferred Arc

Use this default progression unless the user's material clearly demands a different order.

1. Open with a lived question, discomfort, or shift in perspective.
2. Explain why this question matters now.
3. Show how the reading changed the shape of the question.
4. Bring in one concrete personal or work example that tested the idea.
5. Expand from that example into a broader interpretation about the user's role, craft, or field.
6. Clarify what the user now wants to hold on to, change, or let go of.
7. Leave room for uncertainty when the topic is genuinely unresolved.
8. End with the user's present stance or next direction, not a generic moral.

## House Style

- Write in Korean.
- Sound calm, reflective, and direct.
- Favor medium-length paragraphs with occasional short concluding lines.
- Use rhetorical questions sparingly and only to move the logic forward.
- Alternate abstract claims with concrete scenes or examples quickly.
- Use personal experience as evidence, not decoration.
- Let the user sound thoughtful and grounded, not performative or grandiose.
- Keep the prose readable and warm, but never loose or diary-like.

## Non-Negotiables

- Start from the user's real question, not from a summary of the source material.
- State the core thesis by the first third of the piece.
- Give each major section a distinct job; do not let sections repeat the same claim.
- Explain why a source mattered to the user, not only what the source said.
- Keep the reader oriented with clear transitions.
- End with a specific stance, practice, or direction that feels earned.

## Source Integration Rules

- Paraphrase sources instead of leaning on long quotations.
- Do not summarize each reference one by one unless the user explicitly asks for that format.
- If multiple references say similar things, synthesize them into one stronger argument.
- If the user provides overlapping drafts, mine them for original scenes, concerns, and phrasing, then rewrite from scratch.
- Keep the user's perspective dominant. The references should support the argument, not replace it.

## Output Rules

- Default to markdown.
- Use simple heading hierarchy.
- Use lists only when the content is naturally list-shaped.
- When writing for this repository, follow the existing front matter and permalink patterns already used in nearby posts.
- When the user asks for a polished post, deliver the full draft unless they explicitly ask for an outline first.

## Quality Check

Before finishing, confirm all of the following:

- The opening question feels specific and lived-in.
- The post has one dominant thesis.
- Each major section advances the argument instead of restating it.
- At least one concrete personal or work example anchors the piece.
- The user's own conclusion is clearer than the borrowed ideas from the references.
- The ending sounds like the user's current stance, not a generic inspirational wrap-up.
