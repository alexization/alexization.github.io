# 문장 다듬기 원칙

## 1. 문장의 주체를 분명하게 하기

- 사람이 하는 행동은 사람을 주어로 두세요.
- 도구, 시스템, 기술 이름을 불필요하게 주어로 세우지 마세요.
- 가능하면 능동형을 사용하세요.
- 다만 시스템이나 도구의 동작 원리를 설명하는 문장이라면 도구를 주어로 둘 수 있습니다.

예시:

- 덜 좋음: `SDK가 오류를 쉽게 해결해 줍니다.`
- 더 좋음: `오류 원인을 확인한 뒤 SDK 설정을 수정하세요.`

## 2. 필요한 정보만 남기기

- 문장을 짧고 간결하게 유지하세요.
- 이미 문맥상 분명한 내용은 반복하지 마세요.
- 메타 담화를 줄이세요.

예시:

- 덜 좋음: `이제부터 로그를 확인해 보도록 하겠습니다.`
- 더 좋음: `로그를 확인하세요.`

## 3. 구체적으로 쓰기

- 추상 명사보다 동사를 우선하세요.
- 모호한 표현보다 구체적인 행동과 결과를 쓰세요.
- 가능하면 조건, 입력, 출력, 기대 결과를 드러내세요.
- 누가, 무엇을, 어디에, 어떻게 하는지 빠뜨리지 마세요.
- 업계 은어보다 실제 동작을 이해할 수 있는 표현을 쓰세요.
- 가능하면 수치, 단위, 기준, 임계값을 함께 제시하세요.
- 앞뒤 문맥에서 다시 사용하는 변수, 설정값, 단계는 어디에서 쓰이는지 또는 어디에서 왔는지 함께 설명하세요.

예시:

- 덜 좋음: `설정을 적절히 변경합니다.`
- 더 좋음: 환경 변수 `API_URL`을 스테이징 주소로 바꾸세요.

## 4. 자연스러운 한국어 표현 쓰기

- 번역체 표현을 그대로 옮기지 마세요.
- 불필요한 한자어와 군더더기를 줄이세요.
- 사용자가 실제로 읽고 이해하기 쉬운 문장을 우선하세요.

예시:

- 덜 좋음: `다음의 섹션에서 해당 기능에 대한 설명을 제공할 것입니다.`
- 더 좋음: `다음 섹션에서 이 기능을 설명합니다.`

## 5. 일관되게 쓰기

- 공식 기술 용어를 따르세요.
- 같은 개념은 같은 이름으로 반복해서 부르세요.
- 약어는 처음에 풀어쓴 뒤 같은 문서 안에서 일관되게 사용하세요.
- 외래어 표기는 사용 빈도와 독자 친숙도를 고려해 정하세요.
- 공식 문서의 표기와 대소문자를 우선하세요.
- 맞춤법상 표기보다 업계에서 압도적으로 널리 쓰이는 표기가 있으면 그 표현을 우선 검토하세요.

예시:

- 문서 앞부분에서 `Application Programming Interface(API)`라고 썼다면 이후에는 `API`로 통일하세요.
- `설정 값`, `옵션`, `파라미터`처럼 비슷하지만 다른 말을 섞어 쓰지 말고 맥락에 맞는 하나를 고르세요.

## 최종 문장 점검 체크리스트

- 누가 무엇을 해야 하는지 바로 보이나요?
- 한 문장에 정보가 너무 많이 들어가 있지 않나요?
- 추상적인 표현을 구체적인 행동으로 바꿀 수 있나요?
- 번역체나 군더더기 표현이 남아 있지 않나요?
- 같은 개념을 다른 이름으로 반복하고 있지 않나요?
